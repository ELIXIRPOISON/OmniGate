# 14 · Retro, and the v1.1 backlog

Written at v1.0. Nine sprints planned across nine weeks; the work landed in eight days, which is
worth being suspicious of rather than proud of, and the retro says why.

## What the plan got right

**Async by default for the model stage.** Written into `docs/06` as a design assertion before there
was any evidence. It turned out to be right for a reason nobody had guessed: a local 7B classifies in
1.29 s against an 800 ms sync budget, so a sync route backed by one fails open on every request. The
assertion survived contact with measurement.

**Writing the rate limiter rather than installing one.** It is the piece most worth showing: one
atomic Lua call evaluating every applicable bucket, all-or-nothing, with a refused request consuming
nothing anywhere. An off-the-shelf package would have been three lines and nothing to talk about.

**Fail-open everywhere except auth and rate limiting.** The chaos test pays this back directly:
Redis stopped for ten seconds mid-run, zero 5xx, 1,113 degraded responses, recovery in about a
second.

**Committing the artefacts.** k6 summaries, the eval sweeps, the threshold CSVs. It costs nothing at
the time and it is the difference between claiming something and having measured it.

## What the plan got wrong

**The evaluation was a self-test and nobody noticed for three sprints.** `docs/06` specified a
200-row labelled dataset with precision and recall targets, and the delivery plan treated hitting
them as the gate. The dataset was generated by a script written alongside the heuristics it scored.
Recall 0.900 on it; **0.065** against CSIC 2010. Everything downstream of that number — the
threshold, the gate rate, the cost model — was tuned against fiction.

The plan should have required a dataset the project did not write. That is one line in `docs/09` and
it would have changed the shape of three sprints.

**"LLM-assisted" was the headline and is the weakest part.** The project is named for it. On real
attack data the model recovers four requests in 1,254. The strongest detector turned out to be a
forty-line schema learner that was not in the plan at all, because nobody had looked at what the
misses actually were.

**Nine sprints of estimates were wrong in both directions.** The backend landed far ahead. The
detection work, budgeted as one sprint, produced four rounds of measurement, two failed experiments
and a re-plan. The parts that are just building are predictable; the parts that are finding
something out are not, and the plan treated them identically.

**The image size target was inherited, not derived.** `docs/08` asked for under 250 MB. `node:22-alpine`
is 171 MB empty and Prisma 7 ships a WebAssembly query compiler per database. 392 MB is what this
stack costs. The target was copied from somewhere without checking it was reachable.

## What was learned the expensive way

**A dataset you generate measures your own assumptions.** The 14× gap is the single most useful
number produced, and it took three sprints to look for.

**An obvious fix can be worse than the bug.** The prompt taught the model to echo the heuristic
score. Withholding that score took recall from 0.900 to 0.433, because the score was the best feature
it had. The failed experiment is in `docs/results/anomaly-eval.md` on purpose: it found the real bug,
which was that a weak model could *lower* a confident finding.

**Measure a candidate before adding it.** Six patterns were tested against 97,065 rows; five were
added and one — flagging a lone quote in a parameter, which felt obviously right — was rejected at
precision 0.457.

**Safety rules cost recall and are worth it.** Requiring three distinct callers before a parameter
name counts as legitimate costs about twelve points against an idealised learner. Without it the
schema is teachable by one attacker.

**Rendering finds what reading does not.** Charts collapsing to a single dot, KPI text wrapping to
three lines, a CSP blocking the theme script, `HEAD /` returning 404 while browsers got 200. None of
those were visible in the code.

## The honest state of it

Genuinely good: the limiter, the fail-open behaviour under chaos, the audit log, the one-container
deploy, the schema learner, and an evaluation that reports its own negative results.

Genuinely unfinished: the behavioural half of detection is unmeasured, the schema safeguards have
never met a real deployment, and the feature the project is named for is a rounding error.

Not deployed. The quick start works and the image is smoke-tested, but no public URL exists.

## v1.1 backlog

Ordered by evidence rather than appeal.

| # | Item | Why |
|---|---|---|
| 1 | Honeypot deployment | The only way to measure the behavioural half and the only way to test the schema safeguards. Also produces a dataset nobody curated. |
| 2 | Per-route value-range learning | Parameter tampering is the largest remaining miss category and no pattern reaches it. |
| 3 | Use the model's verdict, not only its score | The verdict was right in all fourteen probe classifications while the number never was. Enforcement keys off the number. |
| 4 | Feed `reviewLabel` back | The dashboard writes analyst labels and nothing reads them. That is a free, human-verified dataset from real traffic being discarded. |
| 5 | Golden-set regression gate in CI | Any prompt or threshold edit is currently a coin flip. |
| 6 | Shadow mode | Run a candidate model or prompt in parallel, enforce neither, compare on real traffic. |
| 7 | Policies UI | Rate limiting is the core feature and policies are API-only. |
| 8 | Request-ID lookup in the dashboard | Backend and index exist; the UI does not expose the single most common operator action. |
| 9 | Keyset pagination on logs | Hard-capped at 1,000 server-side, 200 client-side, no cursor. |
| 10 | Audit sampling for 2xx | 377 MB per million requests with no way to sample successful traffic. |
| 11 | Adversarial suite | The prompt says payloads are data; that is untested. An attacker can read the source. |
| 12 | Cross-principal correlation | One attacker across fifty API keys currently looks like fifty quiet callers. |
| 13 | Finer value-shape representation | Four bits costs 28 false positives. A better encoding may buy the same recall for less. |
| 14 | Token bucket alongside sliding window | Burst-tolerant limiting, in the original plan, never started. |

Items 1 and 2 are worth more than the rest combined.
